## Synthesis

**Scope of this page.** Covers the three software-application categories specified in WHO/IAEA's *Technical specifications of radiotherapy equipment for cancer treatment* (2021) (MP Library/Technical specifications of radiotherapy equipment for cancer treatment.pdf): the external beam treatment planning system (TPS, Section 3.6), the oncology information system (OIS, including record-and-verify, Section 3.7), and the brachytherapy TPS (Section 4.5). These are the software layer connecting the imaging equipment in [[equipment_simulators-and-imaging]] to the delivery equipment in [[equipment_LINAC-and-cobalt60-teletherapy]] and [[equipment_HDR-brachytherapy-afterloader]].

**External beam TPS — core modules.** Image import/registration (rigid and/or deformable), contouring/segmentation of targets and OARs, automated non-uniform 3D CTV→PTV margin expansion, a "forward planning" environment for manual beam weight/position/wedge/MLC adjustment, photon and electron dose-calculation algorithms (photon: convolution, Boltzmann transport, or Monte Carlo methods specified as acceptable; electron: pencil beam or Monte Carlo), MU calculation for all beam models, dose prescription to a point/volume/isodose line, DVH-based plan review and plan comparison, and DRR generation. A comprehensive beam-modelling module (importing measured beam profiles/output factors, modelling dynamic/fixed/internal wedges, comparing modelled vs. measured data, with security features locking beam data/models against modification) is required — the TPS's dose-calculation accuracy is only as good as this commissioning data, and the specification explicitly ties dose-calculation-grid accuracy to the tolerance criteria in IAEA TECDOC 1540 Table 4.

**External beam TPS — the independent-MU-calculation recommendation.** The report states a "strong international recommendation" that every patient treatment plan's monitor units (or treatment time) be independently verified — by a separate calculation, not merely re-running the TPS algorithm — before first treatment, or before 10% of prescribed dose is delivered if pre-treatment verification is impossible (e.g. emergency treatment). For simple 2D/3D plans this can be done manually or via spreadsheet; for complex/modulated plans, dedicated independent-calculation software is recommended, though the report deliberately does not specify a technical standard for such software, instead urging departments to either build or purchase one. A related, distinct recommendation: patient-specific pre-treatment dosimetry measurement (radiochromic film, a 2D electronic detector array, or a properly commissioned EPID) for IMRT/VMAT or other complex non-routine techniques, confirming both TPS dose calculation and correct TPS-to-delivery-unit data transfer — two separate verification layers (independent MU calculation vs. measured dosimetry) addressing different failure modes.

**Oncology information system (OIS) — evolution from record-and-verify.** The OIS is described as having evolved from the narrower record-and-verify system (RVS), which only confirmed that treatment-unit parameters matched the plan and logged delivery; a modern OIS additionally transfers plan data/reference images from the TPS to the treatment unit, records per-fraction dose-delivery data and images, includes an image-review module, manages the patient care pathway (tasks, schedules, appointments), and maintains the electronic patient record. Connectivity: DICOM RT for radiotherapy-specific data, HL7 for hospital information system integration (patient administrative data, retrieve-only per the specification — the OIS is not intended to be the authoritative source of patient demographic data), and PACS connectivity for image transfer. Workstation-level software features specified include hierarchical, role-based security (administrator/planner/physicist/physician-level access differences), automated cumulative-dose logging (including correct logging across treatment interruption/termination — directly relevant to the "near-miss" and error-tracking obligations discussed in [[standard_IAEA-medical-physics-ethics]]), and a WHO ICD-11 diagnosis library for statistical reporting.

**OIS — data-security framing.** The report treats OIS implementation as introducing a genuine, non-trivial information-security risk (patient data, treatment plans, and delivery records concentrated in one networked system) — recommending departments engage dedicated IT professionals, maintain UPS-backed automated daily backup (with auto-detect/auto-shutdown within 20 minutes of a power failure), and plan explicitly for backup, archival, and retrieval, framing this as inseparable from clinical safety rather than a purely administrative IT concern.

**Brachytherapy TPS.** A distinct, smaller-scope application: dose optimization based on points, planes, or volumes, using catheter/applicator geometry and source dwell positions reconstructed from isocentric, orthogonal, or semi-orthogonal 2D images (from the C-arm fluoroscopic unit or conventional simulator — see [[equipment_simulators-and-imaging]]) or from CT/MRI. Requires a maintained reference-data library (dosimetric characteristics of each applicator type offered, and of the source itself) and hierarchical password-controlled access to source calibration/modelling parameters — paralleling the external-beam TPS's beam-data protection requirement. Software for automatic online transfer of the approved treatment plan directly to the afterloader control panel is required — a direct, plan-to-delivery data path structurally analogous to the external-beam TPS-to-OIS-to-treatment-unit chain, but shorter (no separate OIS layer is specified as mandatory for brachytherapy in this report, though nothing precludes using the same OIS for both).

**QA emphasis common to all three systems.** Software upgrades are singled out as a specific risk across all three specifications — the report recommends upgrades occur outside patient treatment hours, with new features thoroughly commissioned before clinical release, and (where feasible) a test environment independent of the clinical system for pre-release testing. This echoes the "prudence and precaution" principle (new technology requires adequate proof before clinical use) already documented in [[standard_IAEA-medical-physics-ethics]].
